# PHASE 6 — FRONTEND UI/UX DESIGN & DESIGN SYSTEM

## Context

Backend Security: PASS
Frontend Architecture/Migration: PASS
Supabase: COMPLETELY REMOVED

Current architecture:

Browser → ASP.NET Core API → Database

The following security controls are already implemented and MUST NOT be broken:

- Authentication
- JWT authorization
- Admin authorization
- Permission enforcement
- IDOR protection
- Server-side price calculation
- Payment integrity
- Inventory concurrency
- Transaction atomicity
- Backend business rules

Security hardening items classified as LOW/DEFERRED are intentionally postponed.

DO NOT spend this phase fixing:

- JWT localStorage → HttpOnly cookies
- E2E automation
- CSP hardening
- dependency upgrades
- production security headers
- other LOW/DEFERRED security findings

Focus ONLY on FRONTEND DESIGN, UX, DESIGN SYSTEM and UI IMPLEMENTATION.

==================================================
1. AUDIT CURRENT FRONTEND
==================================================

Before changing UI, inspect the existing frontend:

- React structure
- routing
- pages
- components
- layouts
- forms
- authentication screens
- product pages
- cart
- checkout
- order history
- admin dashboard
- admin product management
- admin order management
- loading states
- error states
- empty states

Do not rewrite working API integration.

Identify:

- reusable components
- duplicated UI
- inconsistent styling
- layout problems
- responsive issues
- accessibility issues
- UX friction

==================================================
2. DEFINE DESIGN DIRECTION
==================================================

Create a coherent visual direction for the entire ecommerce application.

Define:

### Brand

- visual personality
- brand tone
- design principles
- visual hierarchy

### Typography

Define:

- primary font
- fallback fonts
- heading hierarchy
- body text
- labels
- captions
- buttons
- numeric/price typography

Avoid excessive font families.

### Color System

Define semantic tokens:

- primary
- secondary
- accent
- background
- surface
- foreground
- muted
- border
- success
- warning
- destructive
- info

Include accessible contrast.

### Spacing

Define a consistent spacing scale.

### Radius

Define:

- buttons
- cards
- inputs
- modals
- badges

### Shadows

Use a consistent elevation system.

13. ACCESSIBILITY

Implement:

- semantic HTML
- keyboard navigation
- visible focus states
- accessible labels
- appropriate aria attributes
- sufficient color contrast
- usable form validation
- screen-reader-friendly states

Do not use color alone to communicate state.

==================================================
14. UX STATES

Every important interaction must define:

Idle
Loading
Success
Error
Empty
Disabled

Examples:

- Add to cart
- Checkout
- Login
- Register
- Product loading
- Order loading
- Admin mutations

Avoid blank screens.

==================================================
15. MOTION

Use subtle animation only where it improves UX.

Examples:

- hover
- button feedback
- modal transition
- drawer transition
- page transition
- cart feedback

Avoid excessive animations.

Respect:

prefers-reduced-motion

==================================================
16. IMPLEMENTATION RULES

IMPORTANT:

- Preserve existing API contracts.
- Preserve existing routes unless there is a strong UX reason.
- Preserve authentication behavior.
- Preserve authorization behavior.
- Preserve backend business logic.
- Do not reintroduce Supabase.
- Do not add client-side business authority.
- Do not store secrets in frontend code.
- Do not rewrite backend APIs merely to simplify UI.

Reuse existing infrastructure whenever possible.

==================================================
17. DESIGN QUALITY BAR

The result should feel like a production ecommerce product.

Avoid:

- generic template appearance
- excessive gradients
- excessive rounded cards
- inconsistent spacing
- random colors
- too many font families
- giant unnecessary headings
- visually noisy dashboards
- desktop-only layouts

Prioritize:

- hierarchy
- whitespace
- consistency
- readability
- conversion
- accessibility
- responsive behavior

- no secrets are introduced
